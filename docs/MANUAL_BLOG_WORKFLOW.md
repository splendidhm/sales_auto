# 대화 기반 블로그 운영 안내

현재 운영 기준: 2026-10-26. HPL 인스타그램 콘텐츠의 블로그 확장판으로 부동산·금융 중심의 다양한 주제를 다룬다. 초기 발행은 하루 1개 이하이며 수동 요청·검토 후 사용자가 네이버에 직접 게시/예약한다. Plus 이용 환경의 한도 내에서 작업하고 API로 자동 전환하지 않는다. 편집 기준은 [통합 편집 지침](BLOG_EDITORIAL_GUIDE.md)에 모아 관리한다.

## 시작하기

1. 아래 명령을 프로젝트 루트에서 한 번 실행해 로컬 기록 공간을 준비한다. 기존 파일은 덮어쓰지 않는다.

```powershell
New-Item -ItemType Directory -Force -Path 'data/manual-blog/posts' | Out-Null
if (-not (Test-Path -LiteralPath 'data/manual-blog/POST_LOG.md')) {
    Copy-Item -LiteralPath 'docs/templates/POST_LOG.md' -Destination 'data/manual-blog/POST_LOG.md'
}
```

2. 글마다 `data/manual-blog/posts/날짜-주제` 폴더를 만들고 `docs/templates/POST_BRIEF.md`를 `brief.md`로 복사한다. 같은 폴더가 있으면 새 이름을 선택한다. 폴더 생성일과 실제 게시일은 다를 수 있다.
3. 대화에 주제·작성 방식·최근 게시 기록·필요한 자료를 제공한다. 대화 기억만으로 과거 글을 관리하지 않는다. 로컬 경로를 전달하는 것만으로 사진이 첨부된 것은 아니므로 사용하는 대화 환경에서 사진도 제공한다.
4. 최종 원고는 `final.md`, 원본 사진은 `originals/`, 게시에 사용할 이미지는 `images/`에 보관한다. 수정 전 원고는 별도 버전 파일로 남긴다.
5. 직접 게시한 뒤 게시일과 URL을 게시 기록과 해당 글의 작성 기록에 입력한다. 초안이나 예약만 완료한 글을 게시 완료로 기록하지 않는다.

`data/`는 Git 제외 대상이다. 실제 사진·원고·운영 기록은 이곳에 보관하고, 공개 저장소에는 빈 양식과 운영 지침만 올린다. 필요한 경우 사용자가 별도 로컬 백업을 한다. 자동 백업 기능은 없다.

## 작성 요청 예시

### AI 글쓰기

```text
작성 방식: AI 글쓰기
주제:
독자에게 전달할 내용:
참고 자료 또는 확인된 사실:
HPL 인스타그램 원본 링크/파일(선택):
최근 글 구성: 첨부한 POST_LOG.md 참고
먼저 제목 후보 3개와 개요·본문을 작성해 주세요.
확인되지 않은 사실은 검토 목록으로 분리하고 사용 경험을 만들지 마세요.
이미지는 본문 검토 후 별도로 요청하겠습니다.
통합 편집 지침에 따라 카테고리·글 유형·검증 보고서도 정리해 주세요.
썸네일·시각 디자인 지침은 아직 미정입니다.
```

본문 검토 후 필요한 이미지의 수·역할·장면을 요청한다. 이미지 수에 고정 기본값을 두지 않는다. 생성 이미지는 설명용으로 구분하고 실제 방문·사용·제품 촬영의 증거처럼 표현하지 않는다. 이미지를 실제 생성할 때 해당 환경의 이미지 생성 기능과 지침을 사용한다.

### 내 사진 글쓰기

```text
작성 방식: 내 사진 글쓰기
주제:
사진별 설명:
직접 경험한 내용:
방문·사용 시점 및 확인한 가격 등:
최근 글 구성: 첨부한 POST_LOG.md 참고
제공한 사진으로 제목 후보 3개, 개요·본문, 사진 순서·캡션을 작성해 주세요.
사진만 보고 맛·가격·날짜·사용 소감을 추측하지 마세요.
추가 AI 이미지는 만들지 마세요.
```

사용자 경험과 눈으로 확인되는 내용을 구분한다. 정보가 부족하면 필요한 사실을 질문하거나 해당 서술을 제외한다. 원본 사진은 보존하며, 위치 등 개인정보는 사용자가 게시 전에 확인한다. 자동 EXIF 제거·사진 편집은 아직 구현하지 않았다.

## 기록과 편집 기준 적용

글별 `brief.md`에 통합 편집 지침에 따른 카테고리·유형·구성 차이·HPL 재검증·검증 보고서를 남긴다. `POST_LOG.md`는 게시 목록만 관리한다. [주기·월별 운영 기록](templates/OPERATIONS_REVIEW.md)을 로컬 `data/manual-blog/`에 복사해 20편 카테고리 현황, 후보 평가, 월별 성과를 정리한다. 템플릿 갱신 시 기존 기록을 덮어쓰지 말고 필요한 필드를 추가한다.

문체·분량·해시태그·검증 규칙은 통합 편집 지침을 따른다. 썸네일·시각 디자인·이미지 규격만 후속 지침을 기다린다. 기록 양식은 포스팅 디자인 템플릿이 아니다.

## 운영 시험과 다음 단계

실제 주제·사진·디자인 지침을 받은 뒤 AI 글 1편과 사용자 사진 글 1편을 준비한다. 두 글 모두 요청 방향, 사실·경험 정확성, 구성 차이, 수동 게시 편의성, 최종 자료 보존을 확인한다. URL은 사용자가 게시 후 전달하거나 직접 기록한다.

게시물이 쌓이면 기록에 남긴 반복 작업과 불편을 기준으로 반복 입력 → 자료 정리 → 구성 중복 확인 → 초안 생성 순으로 자동화 우선순위를 정한다. 도입 시점·API 예산·공급자는 다시 결정한다. 현재 특정 모델, 월 API 예산, 이미지 수를 확정하지 않는다.

기존 Streamlit 앱은 상품 연결, 월·수·금, 날짜당 한 편 제한이 남아 있다. 다양한 주제 운영을 위해 가짜 상품이나 일정을 만들지 말고 위 로컬 기록으로 운영한다. 상품 없는 원고, 사진 관리 화면, API 생성은 후속 검토 대상이다. 하루 두 슬롯 확장은 현재 발행 기준에서 제외한다. 쇼핑커넥트는 실제 연동 이후 필요한 글부터 적용하며 기존 글을 일괄 제휴 글로 전환하지 않는다.
