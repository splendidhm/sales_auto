# 네이버 블로그 편집 지침 — 통합 v1.1

2026-10-26. 사용자 제공 「Naver Blog Auto Writing 운영 지침 v1.0」을 기존 수동 운영 방식에 통합했다. 편집 기준은 이 문서, 작업·파일 관리 절차는 [수동 운영 안내](MANUAL_BLOG_WORKFLOW.md)가 기준이다. 이후 사용자 지침이 우선한다.

## 1. 목적과 현재 운영 범위

HiddenPatternsLab 인스타그램 콘텐츠를 블로그 독자에게 맞게 확장하는 정보성 블로그다. 검색 사용자의 궁금증 해결, 원본성, 사실 정확성, 자연스러운 개인 블로그 문체와 장기적인 신뢰를 우선한다. 주제를 제한하지 않되 부동산·금융을 중심축으로 운영한다.

현재는 사용자가 Plus 이용 환경에서 수동 요청하고 AI가 조사·초안·이미지 작업을 보조한다. API 호출, 예약 실행, 자동 수집·검사·성과 연동 기능이 구현된 것은 아니다. 한도 도달 시 유료 API로 전환하지 않는다. 초기 실제 발행은 한국 시간 기준 하루 1개 이하이며 쉬는 날을 허용한다. 초안 준비량과 실제 발행량은 구분한다. 사용자가 최종 검토 후 네이버에 직접 게시하거나 예약하고 발행 결과를 기록한다.

## 2. 카테고리 운영

| 주 카테고리 | 목표 비중 | 20편 기준 |
|---|---|---|
| 부동산 | 35% | 7편 |
| 금융·투자 | 30% | 6편 |
| 사회이슈 | 20% | 4편 |
| 일상·생활 | 10% | 2편 |
| 여행·과학 | 5% | 1편 |

실제 신규 발행 20편을 한 주기로 집계한다. 수정 게시·초안·예약·미게시 글은 새 발행으로 중복 계산하지 않는다. 글마다 주 카테고리 하나를 정하고 보조 태그는 집계하지 않는다. 여행·과학은 합쳐 한 카테고리다. 시의성·품질에 따라 조정하되 완성된 주기에서 부동산+금융은 12~14편(60~70%)을 목표로 한다. 진행 중 비중은 편차를 표시하고 부족한 분야를 다음 후보 선정에 반영한다. 비중을 맞추려고 검증되지 않은 글을 발행하지 않는다.

## 3. 요청에 따른 주제 발굴

사용자가 주제를 주면 해당 주제로 진행하고, 후보 추천을 요청하면 최신 뉴스·정부 발표·한국은행/통계청/금융감독원 등 공식 통계·확인 가능한 검색 관심 자료·사용자가 제공한 HPL 콘텐츠·생활/여행/AI/과학 자료를 조사한다. HPL 자료 접근권한이나 계정 연결을 가정하지 않는다.

| 평가 항목 | 배점 |
|---|---|
| 검색 수요·관심도 | 25 |
| 시의성 | 20 |
| 실생활 연관성 | 25 |
| 정보 신뢰성·확보 가능성 | 20 |
| 기존 글과 차별성 | 10 |

점수는 편집 판단이며 실제 검색량이 아니다. 후보마다 근거·확인일과 각 항목 점수를 기록한다. 검색 데이터가 없으면 검색 수요 점수에 ‘추정’을 표시하고 측정값은 ‘미확인’으로 남긴다. 총점과 함께 근거 충분성·카테고리 부족분을 판단한다. 높은 점수도 검증 실패를 상쇄하지 못한다.

전체 게시 기록에서 같은 주제를 확인하고 최근 최대 20편의 제목·본문·구성을 상세 비교한다. 본문을 제공받지 못했다면 제목·기록만 비교했다고 명시한다. 질문·근거·결론이 동일한 후보는 제외하고, 같은 소재라도 새 제도·새 데이터·다른 독자 질문이 있으면 관련 이전 글과 차이를 기록한 후 후보로 남길 수 있다.

## 4. 글 유형과 문체

| 유형 | 적용 |
|---|---|
| A 정보 설명형 | 제도·세금·금융상품·원리를 쉽게 설명 |
| B 경제 분석형 | 데이터, 원인, 구조와 영향을 구분해 분석 |
| C 사회이슈 해설형 | 사실관계·이해관계·주요 견해를 근거에 따라 설명 |
| D 비교·추천형 | 제품·금융상품·여행지·주거지역을 명시한 기준으로 비교 |
| E 생활형 | 생활 고민·실용 정보·사용자가 제공한 실제 경험 |
| F 과학·미래기술형 | 질문과 과학 원리·실제 사례를 연결 |

유형은 글의 목적이며 고정 템플릿이 아니다. 사진 중심 기록형·질문답변형·단계 설명형·이야기형 등은 각 유형 안에서 사용할 전개 방식이다. 주제에 맞는 유형 하나를 정하고 도입·전개·사진 배치·마무리를 별도로 설계한다. 같은 유형을 연속 선택할 수 있지만 직전 글과 같은 구성 조합·상투 문구는 바꾼다.

- 자연스러운 존댓말, 쉬운 용어 풀이, 모바일에서 읽기 쉬운 짧은 문단을 사용한다. 보고서 말투·과장된 감탄사·불필요한 이모티콘을 줄인다.
- 독자의 궁금증을 중심에 두되 질문형 시작을 매번 강제하지 않는다. 숫자·상황·비교·관찰로도 시작할 수 있다. ‘안녕하세요, 오늘은 ~ 알아보겠습니다’의 반복을 피한다.
- 기본 본문은 공백 포함 약 1,000~2,000자, 심층 분석은 필요시 2,500~3,000자. 제목·해시태그·별도 검증 보고서는 본문 분량에서 제외한다. 분량 채우기보다 완성도를 우선한다.
- 소제목은 필요시 2~4개, 문단은 대체로 2~4문장. 비교에 도움 될 때 표·숫자를 사용한다. 제목은 내용과 일치하는 자연스러운 검색형으로 후보 3개를 제시한다.
- 해시태그는 글마다 10~20개, 기본 15개를 제안한다. 주제와 직접 관련된 핵심 검색어·인기 관심어·시의성 있는 이슈 키워드를 우선하고 세부 질문·지역·제도명으로 보완한다. 이는 내부 편집 기준이며 네이버 플랫폼의 입력 한도를 뜻하지 않는다.
- 작성 시 확인 가능한 검색 관심 자료와 최신 공식 발표·뉴스를 참고한다. 검색 인기와 뉴스의 시의성을 구분하고, 실제 검색량·순위를 확인하지 못하면 ‘주제 기반 후보’로 기록한다. 이슈·인기라는 이유로 본문에 없는 사건·지역·상품이나 발표되지 않은 정책을 태그에 넣지 않는다.
- 표기만 다른 중복 태그·무관한 인기 태그를 제외한다. 본문에 맞는 태그가 부족하면 억지로 수를 채우지 않고 이유를 남긴다. 태그 수를 늘리더라도 본문 키워드 반복이나 노출 보장을 하지 않는다.
- 실제 경험이 없으면 체험담·사용 후기를 만들지 않는다. 사용자의 경험과 사진 관찰, 확인된 사실과 해석을 구분한다.

## 5. HPL 원본과 이미지 활용

인스타그램 카드뉴스의 질문·분석 관점·핵심 데이터를 출발점으로 삼되 카드 문구를 이어 붙이지 않는다. 배경 설명, 독자에게 미치는 의미, 비교 사례와 한계를 추가해 별도 원고로 쓴다. 원본 링크/파일·작성일·추가한 관점·재검증 결과를 글 기록에 남긴다. 원본이 제공되지 않으면 확인한 것으로 주장하지 않는다.

수치는 최신 원자료로 재검증하며 틀리거나 변경된 정보는 수정한다. HPL 이미지는 필요할 때 일부 사용하고 권한·맥락을 확인한다. 모든 글에 브랜드명을 강제 노출하지 않는다. 다른 매체 원문을 단순히 바꿔 쓰지 않는다. 기존 HPL 웹사이트 코드는 별도 프로젝트로 유지하며 이번 통합으로 수정·발행하지 않는다.

두 이미지 방식은 그대로 유지한다. AI 글쓰기에서는 사용자가 필요한 이미지 수·장면을 요청한다. 내 사진 글쓰기에서는 사용자 사진만 쓰고 별도 요청 없이 생성 이미지나 HPL 카드 이미지를 보충하지 않는다. 생성 이미지는 실물·실제 경험의 증거처럼 쓰지 않는다. 썸네일 디자인·공통 시각 양식·이미지 규격은 후속 지침으로 정한다. 이번 본문 편집 기본값과 구분한다.

## 6. 사실 검증과 승인

- 금융·부동산: 최신 법령·공식 통계·금융기관 자료 우선. 적용일·대상·지역·조건을 확인한다.
- 사회이슈: 공공기관 자료와 복수의 신뢰할 수 있는 보도를 비교하고 확인된 사실과 주장을 구분한다. 근거가 다른 주장을 같은 신뢰도로 포장하지 않는다.
- 여행·생활: 가격·운영시간·규격 등의 기준일과 조건을 명시한다.
- 과학: 논문·연구기관·공식 기술자료를 우선한다.

자료 발표일·적용/관측 시점·확인일을 구분하고 URL을 저장한다. 확인하지 못한 출처·수치를 생성하지 않는다. 사실과 의견을 구분하고 미래 전망의 불확실성을 설명한다. 추천에는 비교 기준과 한계를 밝히며 확인되지 않은 광고 표현·수익 보장을 넣지 않는다.

검증 보고서는 글별 기록의 표에 ‘주장/출처/자료 기준일/확인일/확인 결과/남은 조치’를 정리한다. 주요 주장 미확인이나 상충 자료가 남으면 보류하고, 해결하거나 주장을 제외한 뒤 다시 검토한다. 제목·본문·이미지·캡션을 함께 확인한다. 대가성 콘텐츠 고지와 AI 이미지 표시의 적용 여부는 게시 시 최신 공식 기준을 확인하고 결과를 기록한다. 쇼핑커넥트는 실제 연동 후 필요한 글에만 적용한다.

## 7. 수동 실행 순서

1. 사용자 주제 또는 요청에 따른 후보 수집 → 카테고리 현황·점수·중복 확인.
2. 사실·출처 조사 → 글 유형과 다른 구성 선택 → 제목 후보 3개와 본문 작성.
3. 문체·가독성 검토 → 요청된 이미지/사용자 사진 연결 → 검증 보고서 정리.
4. 사용자 수정·승인 → 사용자가 네이버 직접 게시/예약 → 실제 발행 확인 후 URL·기록 저장.

예약 완료는 발행 성공이 아니다. 발행 기록은 사용자가 확인한 결과인지 온라인 확인을 거친 결과인지 구분한다. 현재는 승인 후에도 자동 발행하지 않는다. 향후 게시 자동화는 공식적으로 허용된 수단과 권한을 확인한 경우에만 별도 설계하며 방어 장치 우회나 비공식 매크로를 도입하지 않는다.

## 8. 성과와 개선

월별로 발행 수·카테고리 수, 조회수, 확인 가능한 검색 유입/키워드, 댓글·공감, 글별 성과, 작성·검수 시간을 수동 기록한다. 지표마다 관측일·출처·집계 기간을 붙이고 알 수 없는 값은 0 대신 ‘미확인’으로 둔다. 누적값과 기간값을 혼합하지 않는다. 20편 운영 주기와 월별 분석은 별개다.

월별 기록에서 다음 달 주제 선정·프롬프트와 반복 작업 개선점을 정한다. 수동 측정 자료 없이 성과를 추정하지 않는다. 구성 다양화·자동화가 계정 안전, 검색 순위 또는 노출 상승을 보장한다고 표현하지 않는다. API 공급자·예산·자동화 시점은 데이터가 쌓인 후 재결정한다.
